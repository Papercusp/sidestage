The Board vs The Panel

SideStage already ships a live-auction UI. The landing page grew a second one. Below, both are driven by the same auction — same lot, same clock, same bids — so the only thing that differs on screen is how each one presents it.

Read first

These are not two versions of the same thing. The Panel is a working bidding UI wired to the server. The Board is a scripted marketing animation with no bidding in it at all. The question is not which to keep — it is which parts of the Board's visual language are worth moving into the Panel.

Recommendation

Keep the Panel. Give it the Board's clock.

Don't swap — graft

Replacing the Panel would mean rebuilding bidding, sync, the three non-happy states and the accessibility work, to gain presentation. The cheaper and better trade is to move four things from the Board into the Panel it already has. Three of them need no new data — the Panel is already receiving everything they render.

  1. The countdown ring replaces the "Time left" box. Same number, but it drains and changes colour. This is the single biggest difference in how urgent the panel feels, and it is pure presentation.
  2. The bid feed replaces the "Bids: 3" count. No new data at all — auction.bids is already in hand and already ordered; the Panel renders bids[0] and discards the rest.
  3. The price becomes the hero. Lift current bid out of the three-up row onto the yellow ticket band, and tween it when it changes.
  4. The close gets staged. Going once / going twice / SOLD, winning row in green. The server already emits the close; only the presentation is missing.

What I'd leave on the landing page

The guard chips (quantity held, bids ordered server-side) are marketing claims aimed at a seller deciding whether to trust the platform. A buyer mid-auction does not need reassuring about the reservation model — they need the price, the clock and the button. Same for 214 watching, which is real data in the app and should read from the event stats rather than be decoration.
